# AI 기반 사용처

> 원본: Notion「AI 기반 사용처」— FX ATLAS에서 AI(생성형 AI/LLM)가 비즈니스 로직상 정확히 어디에 쓰이고 어디엔 쓰이면 안 되는지 정리.
> **핵심 원칙**: AI는 **서술(narrate)·추출(extract) 계층**으로만 쓴다. 계산·사실 생성엔 관여하지 않는다. (요구사항 정의서 NFR-AI-01~03, 예측의 세 층위 L1/L2/L3 설계를 그대로 따름)

## 1. 한 줄 요약

AI는 두 가지에만 쓴다:
1. 이미 확정된 숫자·사실을 **사람이 읽기 좋게 바꾸는 역할**(서술)
2. API로 못 받는 비정형 원문(뉴스 등)에서 **구조화 데이터를 뽑아내는 역할**(추출)

날짜·수치·투자 판단처럼 틀리면 안 되는 것은 AI가 만들지 않는다.

| 구분 | AI 역할 | 근거 |
|---|---|---|
| 계산 결과 서술 | 이미 계산된 숫자를 자연어로 설명 | NFR-AI-01~03 |
| 전망 동인 한 줄 설명 | `forecast_factors` 수치를 문장으로 풀이 | 환율 범위 화면 §6 |
| 비정형 데이터 구조화 | 뉴스 등 원문 → 고정 스키마 추출 | NFR-DT-01 |
| (검토 중) 자연어 목표 입력 | 자유 텍스트 → `goals` 필드 파싱 | 화면 정의서 미결정 항목 |

## 2. AI가 적절한 사용처

### 2.1 계산 결과 설명 (전 화면 공통 서술 계층)
계산 엔진(몬테카를로·손익 분해·버킷 배분)이 만든 숫자를, 사용자의 `display_mode`(초보자/전문가)와 `explain_domain`(finance/dev/marketing/plain 비유 도메인)에 맞춰 자연어로 풀어 쓴다.
- **입력**: 계산 엔진 출력 JSON (예: `{code:"high_vol", vol_percentile:0.88}`)
- **출력**: 고정 스키마 설명 텍스트 (예: "변동성이 5년 상위 12%입니다. 분할 횟수를 늘리는 것을 고려하세요.")
- **안전장치**: 수치 필드를 엔진 원본과 대조해 불일치 시 폐기·재생성(NFR-AI-02), 단정적 방향/투자 권유 표현 후처리 차단(NFR-AI-03), `audit_logs`에 `action='ai_explained'`로 프롬프트·응답 전문 기록
- **화면**: 홈 "주의 필요" 블록, 손익 분해, 플래너 안전 버킷 하한 안내 문구 등

### 2.2 전망 동인(forecast_factors) 서술문
`direction`(+1/-1)·`strength`(0~1)·`latest_value`는 `macro_series` 실측에서 정해진 규칙으로 계산되며 **AI가 만들지 않는다.** AI는 이 수치를 받아 "한미 금리차 확대가 원화 약세 요인으로 작용" 같은 한 줄 설명만 생성.
- **출력**: 참고용 한 줄 설명. 화면엔 반드시 "참고" 배지 + 모델 성적(`model_runs.hit_rate` 등) 병기
- **안전장치**: 2.1과 동일. 규제상 가장 민감한 구간이라 단정적 방향 표현 차단이 특히 중요
- **관련**: FR-FC-06, FR-FC-08, FR-FC-12(L1/L2 계층 분리 강제)

### 2.3 비정형 원문 → 구조화 데이터 추출
공식 API로 못 받는 정보(뉴스 기반 이벤트·시장 코멘터리)를 크롤링한 뒤, 원문을 근거로 고정 스키마 필드를 추출.
```
크롤러가 원문 텍스트 확보 (grounding source, AI 아님)
  → 원문을 프롬프트에 그대로 포함
  → "이 텍스트에서 아래 스키마로 추출" (event_date, region, title, impact 등)
  → 고정 JSON 응답 → 타입·범위 검증 후 insert
```
- **안전장치**: ENUM/범위 벗어난 값은 insert 전 검증, `source_url`·`fetched_at`·`extraction_method`(`official_calendar` vs `llm_extracted`)로 신뢰도 구분(공식 캘린더와 같은 신뢰도로 섞지 않음)
- 구조가 일정한 공식 소스(연준·ECB·한국은행 캘린더, FRED API)는 **AI 없이 CSS 셀렉터/정규식**으로 파싱. 뉴스처럼 구조 없는 원문일 때만 AI 추출.
- **관련**: NFR-DT-01, 화면 정의서 §6 "다가오는 일정"

### 2.4 (검토 중) 자연어 목표 입력 파싱
화면 정의서 미결정 항목. 자유 텍스트("내년 3월까지 유럽여행 300만원 모으고 싶어")를 `goals`의 `currency`/`target_amount`/`target_date`로 파싱. 방향은 2.3과 반대(텍스트→구조화)지만 원리는 같다 — 저장 전 검증(과거 날짜 여부, 금액 범위 등) 필수. **채택 여부 미확정.**

## 3. AI를 쓰면 안 되는 곳

| 항목 | 실제 담당 | 이유 |
|---|---|---|
| 환율 변동성 예측 (L1) | GARCH 계열 통계 모델 | 재현 가능해야 `model_runs` 성적 추적이 의미 |
| 환율 방향 전망 수치 (L2) | 통계/계량 모델 | 근거가 "LLM 판단"이면 모델 투명성(FR-FC-08) 불성립 |
| 몬테카를로·손익 분해·버킷 배분 | 결정론적 계산 엔진 | NFR-AI-01이 명시적으로 금지 |
| 일정의 날짜·발표 여부 자체 | 공식 캘린더/API | LLM은 미래 날짜 recall에 취약, 출처 없는 숫자 금지(NFR-DT-01) |
| 통화별 순위·점수·추천 | 없음(기능 자체가 W, 규제상 배제) | NFR-RG-01 |

## 4. 공통 안전장치 요약

1. **그라운딩**: 파라메트릭 지식으로 답하게 하지 않고, 항상 계산 엔진 출력·크롤링 원문 같은 실제 근거를 프롬프트에 넣어 그 안에서만 답하게 한다.
2. **고정 스키마 + 수치 대조**: 구조화 출력으로 받고, 숫자 필드는 원본과 대조해 불일치 시 폐기·재생성.
3. **표현 후처리 필터**: 단정적 방향 표현("오를 것입니다")·투자 권유 표현을 차단.
4. **출처·감사 기록**: 모든 AI 산출물은 `audit_logs`(서술) 또는 `source_url`/`fetched_at`/`extraction_method`(추출)로 근거를 남긴다.
5. **표현 파라미터와 계산 파라미터 분리**: `display_mode`·`explain_domain` 같은 AI 프롬프트용 설정값은 절대 계산 로직에 들어가지 않는다.
