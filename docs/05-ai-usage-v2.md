## 1. 원칙

> 🎯 AI는 **서술(narrate)** 과 **추출(extract)** 계층에만 쓴다. 계산과 사실 생성에는 관여하지 않는다.
> 점수·금액·범위·등급은 규칙 기반 계산 엔진이 만들고(FR-AI-01), AI는 검증된 JSON의 값만 설명에 사용한다(FR-AI-02).

AI가 하는 일은 두 가지뿐이다.

1. **서술** — 이미 확정된 숫자와 사실을 사용자가 읽기 좋은 문장으로 바꾼다.
2. **추출** — API로 받을 수 없는 비정형 원문에서 고정 스키마 데이터를 뽑아낸다.

날짜·수치·투자 판단처럼 틀리면 안 되는 것은 AI가 만들지 않는다.

| 사용처 | AI 역할 | 근거 요구사항 | 우선 |
|---|---|---|---|
| 계산 결과 서술 | 확정된 숫자를 자연어로 설명 | FR-AI-01~07, NFR-AI-01~03 | M |
| 전망 동인 한 줄 설명 | `forecast_factors` 수치를 참고 문장으로 풀이 | FR-FC-09, FR-FC-12 | S |
| 용어·가정 풀이 | 화면에 이미 있는 값을 다른 표현으로 재설명 | FR-AI-08, 화면 v2 §17 | M |
| 비정형 원문 구조화 | 뉴스 원문 → `econ_events` 스키마 추출 | FR-FC-10, FR-CM-10, NFR-DT-01 | S |
| 자연어 목표 입력 | — | Route 미확정. MVP 범위 밖 | W |

## 2. 예측 계층 L1 / L2

v2에서 계층은 두 개다. 요구사항 v2 §2.2 "예측 정보의 구분" 표와 ERD v3.0 §8 "예측 계층 분리" 콜아웃이 정본이다.

| 계층 | 내용 | 저장 위치 | 계산 입력 | AI 관여 |
|---|---|---|---|---|
| **L1** | 기준선 환율과 예측 범위 · 변동성 | `forecasts.base_rate` · `p50_lo/hi` · `p80_lo/hi` · `fx_stats` | **허용** (Route 설계 후 사용 여부 확정) | 없음. 통계 모델이 산출 |
| **L2** | 방향 참고 경로와 전망 동인 | `forecasts.model_path` · `forecast_factors` | **금지** (FR-FC-12) | 수치를 문장으로 서술만 |
| (금지) | `지금 사라·팔라` 형태의 지시 | — | 금지 | 표현 필터로 차단(FR-AI-07) |

> 🔒 L2는 화면 표시 전용이다. AI가 L2를 서술할 때도 "참고" 배지와 모델 성적(`model_runs.hit_rate` · `coverage_80` · `avg_width`)을 반드시 함께 노출한다(FR-FC-11).

## 3. AI가 적절한 사용처

### 3.1 계산 결과 서술 — 전 화면 공통 계층

계산 엔진이 만든 숫자를 그대로 찍지 않고, 사용자의 설명 선호와 익숙한 분야에 맞춰 자연어로 풀어 쓰는 계층이다.

**개인화 파라미터** (ERD v3.0 §5.2 `user_settings`)

| 컬럼 | 값 | 화면 라벨 |
|---|---|---|
| `explain_level` | `simple` | 핵심과 내 돈에 미치는 영향만 쉽게 |
| `explain_level` | `standard` | 숫자와 이유까지 함께 |
| `explain_level` | `detailed` | 지표와 모델의 한계까지 자세히 |
| `explain_domain` | `finance` / `dev` / `marketing` / `plain` | 익숙한 설명 분야. 비유 소재로만 사용 |

- **입력**: 계산 엔진 출력 JSON. 예: `{"code": "high_vol", "vol_percentile_5y": 0.72, "regime": "elevated"}`
- **출력**: 고정 스키마의 설명 텍스트
- **관련 화면**: 홈 `오늘의 핵심`·`주의 필요`, X-Ray 손익 분해, Fit 관계 설명, Stress Test 해석, Forecast 4문장

> ⚠️ **`explain_level`·`explain_domain`은 표현에만 쓴다.** 같은 사용자·같은 자산이면 세 단계 모두 **동일한 숫자와 동일한 계산 결과**를 보여야 한다. 설명 밀도와 어휘만 달라진다(FR-CM-08, FR-FC-08, FR-AI-03).
> v1의 `display_mode`처럼 사용자 등급에 따라 계산 방식(예: 손익 분해 알고리즘)을 바꾸는 설계는 v2에서 폐기했다.

### 3.2 Forecast 4문장 서술

요구사항 FR-FC-07·FR-AI-04에 따라 **기본 4문장 고정**이다. 문장 수는 설명 선호와 무관하게 유지하고, 각 문장에 담는 내용만 바꾼다(화면 v2 §12 "설명 선호별 출력").

| 설명 선호 | 4문장 구성 |
|---|---|
| `simple` | 결론 · 내 돈 영향 · 주의 · 읽는 법 |
| `standard` | 현재값 · 예측 범위 · 변동성 · 개인 손익 |
| `detailed` | 구간 수준 · 변동성 지표 · 민감도 · 모델 한계 |

세 출력은 **같은 사실과 같은 숫자**를 사용한다.

### 3.3 전망 동인 서술 (L2)

`direction`(±1) · `strength`(0~1) · `latest_value`는 `macro_series` 실측치에서 규칙으로 계산되며 **AI가 만들지 않는다.** AI는 이 값을 받아 한 줄 설명만 생성한다.

- **입력**: `factors.name_ko` · `direction` · `strength` · `latest_value`
- **출력**: 참고용 한 줄 설명. 예: "한미 금리차 확대가 원화 약세 요인으로 작용"
- **필수 병기**: `참고` 배지 + 모델 성적 (FR-FC-09는 S 우선순위, FR-FC-11 투명성)
- 이 문장은 어떤 계산에도 입력되지 않는다(FR-FC-12)

### 3.4 비정형 원문 → 구조화 데이터 추출

공식 API로 받을 수 없는 정보에 한해 사용한다. 크롤링 자체에는 AI가 필요 없고, **원문이 비정형일 때만** AI 추출이 의미가 있다.

```
크롤러가 원문 텍스트 확보 (grounding source, AI 아님)
  → 원문을 프롬프트에 그대로 포함
  → 고정 스키마로 추출 (event_date, region, title, impact)
  → 타입·ENUM·범위 검증
  → econ_events INSERT
```

- **원칙**: 구조가 일정한 공식 소스(연준·ECB·한국은행 캘린더, FRED release API)는 AI 없이 파서로 처리한다. 뉴스처럼 구조가 없는 원문일 때만 AI를 쓴다.
- **신뢰도 구분**: 공식 캘린더 데이터와 LLM 추출 데이터를 같은 신뢰도로 섞어 보여주지 않는다. `source_url` · `fetched_at` · 추출 경로를 함께 남긴다.
- **Mock 단계 주의**: 실제 데이터가 없는 동안 출처를 만들어내지 않는다(FR-CM-10). 시연용 일정은 `시연용 예시 데이터` 배지를 붙인다(FR-CM-02).

## 4. AI를 쓰지 않는 곳

| 항목 | 실제 담당 | 이유 |
|---|---|---|
| 변동성·예측 범위 산출 (L1) | 통계 모델 | 재현 가능해야 `model_runs` 성적 추적이 성립(FR-FC-11) |
| 방향 참고 경로 수치 (L2) | 통계·계량 모델 | 근거가 "LLM 판단"이면 투명성이 성립하지 않음 |
| 위험성향 점수·유형 판정 | 규칙 기반 (A=0~D=3 합산, 0~9) | FR-DG-01, NFR-AI-01 |
| 손익 분해 · 민감도 · 스트레스 계산 | 결정론적 계산 엔진 | NFR-AI-01이 명시적으로 금지 |
| Fit 적합·부적합 판정 | 계산 엔진 (관계 설명만) | FR-FT-04 — 절대적 적합·부적합 표현 금지 |
| 통화별 순위·점수·추천 | **없음. 기능 자체가 W** | FR-FT-06, NFR-RG-01 |
| 경제 일정의 날짜·발표 여부 | 공식 캘린더/API | LLM은 미래 날짜 recall에 취약. 출처 없는 숫자 금지(NFR-DT-01) |
| 안전 버킷 · 분할 회차 · 달성 확률 | **미정. Route 상세설계 확정 전** | 요구사항 v2 §4.12 미확정 목록 |

> 🚫 **v1에서 삭제된 서술**
> v1 §2.1은 몬테카를로·버킷 배분 결과를 AI가 서술한다고 적었고, "플래너 안전 버킷 하한 안내 문구"를 관련 화면으로 들었다. 요구사항 v2 §4.12는 안전·기회 버킷의 존재와 비율, 권장 분할 회차, 몬테카를로 적용 여부, 달성 확률의 정의를 **모두 미확정**으로 선언했다. 해당 서술은 Route 상세설계 확정 후 다시 넣는다.

## 5. 출력 규약과 실패 처리

| 단계 | 규약 | 근거 |
|---|---|---|
| 1. 그라운딩 | 파라메트릭 지식 사용 금지. 검증된 엔진 출력 JSON 또는 크롤링 원문만 프롬프트에 넣고 그 안에서만 답하게 한다 | FR-AI-02 |
| 2. 고정 스키마 | 자유 문장이 아니라 구조화 출력으로 받는다. Forecast 요약은 4문장 고정 | FR-AI-04 |
| 3. 수치 대조 | 응답의 숫자·통화·기간·방향이 엔진 결과와 일치하는지 검사. 불일치하면 폐기 | FR-AI-05, NFR-AI-02 |
| 4. 표현 필터 | 보장·확정·무조건·반드시 매수 같은 단정 표현과 투자 권유 표현을 후처리에서 차단 | FR-AI-07, NFR-RG-01 |
| 5. 폴백 | 생성 실패 또는 검증 실패 시 **고정 템플릿**을 출력한다. 화면과 계산 카드는 그대로 유지 | FR-AI-06, NFR-AI-03, 화면 v2 §20 |
| 6. 감사 기록 | `audit_logs`에 `action='ai_explained'`로 프롬프트·응답 전문을 남긴다. 사용자에게 노출된 경고 문구는 `action='warning_shown'` | ERD v3.0 §10 |

> 🛟 **AI 실패는 서비스 실패가 아니다.** AI가 죽어도 점수·금액·범위·차트는 계산 엔진이 이미 만들어 둔 값이므로 전 화면을 그대로 이용할 수 있어야 한다(NFR-AI-03). AI 응답 대기 때문에 카드 렌더링을 막지 않는다.

### 5.1 급변 상태에서의 AI

급변 상태에서도 **최신 시장 정보와 충격 사실을 숨기지 않는다**(FR-SF-01, 요구사항 §2.3). AI 설명을 중단하거나 화면을 잠그는 방식은 금지한다. 대신 아래를 한다.

- 예측 범위와 오차가 확대될 수 있음을 문장에 반영한다(FR-SF-03)
- 상태 배지(정상 · 주의 · 급변)와 함께 노출한다(FR-SF-02)
- 불확실성이 커진 구간에서는 `detailed` 수준의 한계 문장을 `simple`에서도 최소 1문장 포함한다

## 6. 코파일럿의 위치

화면 v2 §17 기준. 챗봇은 추가 질문을 돕는 창구이며 **기능 전체 조작의 중심이 아니다**(FR-AI-08).

| 하는 역할 | 하지 않는 역할 |
|---|---|
| 화면에 이미 계산된 결과를 다른 표현으로 설명 | 메뉴 전체를 대신 조작 |
| 이해하지 못한 용어 풀이 | 점수·환율·손익 재계산 |
| 현재 시나리오의 가정 설명 | 새로운 추천 비중 생성 |
| 익숙한 분야 기반 비유 제공 | 투자 실행 지시 |
| 진단 결과의 `왜 이렇게 나왔나요?` 보조 설명(FR-DG-07) | 대표 위험성향 재판정 |
